# 実現できるかのテスト（watanabe、2026-10-14）

AIDER を使って、「エッジで軽く分類 → 迷った画像だけサーバーへ送る」を、回線が細くなる条件で動かせるかを小さく試したもの。

## 中身
| ファイル | やること |
| --- | --- |
| `extract.py` | AIDER の全画像を、エッジ役（MobileNetV3-Small）とサーバー役（ConvNeXt-Tiny）に通して特徴量を作る。送るときの JPEG のバイト数も測る |
| `sim.py` | 特徴量から分類器を作り、回線を 10Mbps → 1Mbps → 200kbps と細くしたシミュレーションで、送り方を比べる |
| `results/report_0.5.json` | 0.5秒に1枚で撮影したときの結果 |
| `results/report_0.1.json` | 0.1秒に1枚で撮影したときの結果 |

## 動かし方
1. データを取ってくる（リポジトリの一番上で）: `.\scripts\fetch_external.ps1`
2. ライブラリを入れる（`requirements.txt` を見る）
3. 特徴量を作る（CPU で約30分）
   ```
   python experiments/feasibility/extract.py data/raw/AIDER experiments/feasibility/feats.npz
   ```
4. シミュレーション（数十秒）
   ```
   python experiments/feasibility/sim.py experiments/feasibility/feats.npz experiments/feasibility/results 0.1
   ```
   `feats.npz`（約35MB）は GitHub に入れない（`.gitignore` の `*.npz`）。

## 条件
- AIDER 公開版 6,433枚（平常 4,390、被災 2,043）を、学習 50% / 検証 20% / テスト 30% に分けた（乱数の種は 0）
- モデルは ImageNet で学習済みのものを使い、最後の分類の部分（ロジスティック回帰）だけ学習した
  - EmergencyNet の学習済みの重みは Keras 形式なので、今回は MobileNetV3-Small で代わりにした
- 送る画像は 240×240 の JPEG（品質 85、平均 14KB）
- 送る量は、どの方式も全体の約 40% にそろえた（しきい値は検証用データで決めた）
- 流す順番を変えて 3 回くり返し、平均をとった
- 回線はシミュレーション（Linux の netem で実際に絞ったものではない）。サーバーの計算時間は 0 とした

## 結果の要点
- エッジだけ: macro F1 90.0%、被災の見逃し 5.4% / サーバーだけ: macro F1 94.9%、見逃し 3.3%
- エッジは被災画像 614 枚のうち 33 枚を「平常」と見逃し、そのうち 10 枚は確信度 0.8 以上だった
- 0.5秒に1枚では回線が詰まらず、送る順番を変えても差は出なかった
- 0.1秒に1枚（回線が詰まる）では、被災っぽい順に送ると、被災画像が確認されるまでの平均が 12.5秒 → 6.3秒 に縮んだ。ただし、ほかの方式との差は数秒だった

## テストを見てから変えた点（注意）
- 撮影の間隔: 最初は 0.5秒に1枚で試し、回線が詰まらなかったので 0.1秒に1枚も試した
- 提案の中身: 最初は「被災っぽい画像を送る」だったが、見逃しが増えたので「確信度が低い、または被災っぽい画像を送る」も試した
- どちらも結果を見てから足したもの。本番の実験では、条件を先に決めてから測る
