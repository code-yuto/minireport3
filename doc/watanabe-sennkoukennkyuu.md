# 先行研究まとめ（watanabe）

## テーマ案
- テーマ：エッジとサーバーで分担する災害画像の分類（エッジ・クラウド協調推論）
  - ドローンの軽い AI で画像をふるいにかけ、迷った画像や被災っぽい画像だけをサーバーの重い AI に送る
- もとになる社会課題：災害時は道路が途切れ、被災状況が確かめにくい。基地局も弱るので、ドローンの映像を全部は送れない

### A. 基本のしくみ

### 論文1
- タイトル：NoScope: Optimizing Neural Network Queries over Video at Scale
- 著者・年：Daniel Kang, John Emmons, Firas Abuzaid, Peter Bailis, Matei Zaharia（Proceedings of the VLDB Endowment, vol. 10, no. 11, 2017）
- URL / DOI：https://doi.org/10.14778/3137628.3137664
- 査読：あり（論文誌 PVLDB）
- 何をしたか：
  - 監視カメラの映像を、まず小さく軽いモデルで見て「何も映っていない」フレームを捨てる
  - 迷ったフレームだけを重いモデルに回す（カスケード）
  - 動画と探す物体に合わせて、軽いモデルとしきい値を自動で選ぶ
- 結果（数字があれば数字で）：
  - 重いモデルだけを使う場合と比べて、精度の低下 1〜5% で、265〜15,500 倍の速さ（実時間比）
- 自分のテーマとの違い：
  - 「軽いモデルでふるいにかけ、迷ったものだけ重いモデルへ」という発想は同じ（この分野の基本形）
  - ただし 1 台の計算機の中の話で、回線を通して送る話ではない
  - どのクラスを見逃しても同じ重さで扱っている

### 論文2
- タイトル：Neurosurgeon: Collaborative Intelligence Between the Cloud and Mobile Edge
- 著者・年：Yiping Kang, Johann Hauswald, Cao Gao, Austin Rovinski, Trevor Mudge, Jason Mars, Lingjia Tang（ASPLOS, 2017）
- URL / DOI：https://doi.org/10.1145/3037697.3037698
- 査読：あり（国際会議 ASPLOS）
- 何をしたか：
  - 1 つのモデルを途中の層で切り、前半をスマホ、後半をサーバーで動かす「分割推論」
  - 回線の速さやサーバーの混み具合を見て、どこで切るかを自動で選ぶ
- 結果（数字があれば数字で）：
  - 要旨に数字はない（本文は未確認）
- 自分のテーマとの違い：
  - エッジとサーバーで分担する点は同じ。ただし全部の画像を送る（途中の結果を送る）ので、送る枚数は減らない
  - 今回は「送らない画像を作る」ことで通信量を減らす

### 論文3
- タイトル：Distributed Deep Neural Networks Over the Cloud, the Edge and End Devices（DDNN）
- 著者・年：Surat Teerapittayanon, Bradley McDanel, H. T. Kung（ICDCS, 2017）
- URL / DOI：https://doi.org/10.1109/icdcs.2017.226
- 査読：あり（国際会議 ICDCS）
- 何をしたか：
  - 端末・エッジ・クラウドの 3 段にモデルを分けて置き、まとめて学習する
  - 端末で自信があればそこで答えを出し、なければ上の段に送る
- 結果（数字があれば数字で）：
  - 生のデータをすべてクラウドに送る方式と比べて、精度を保ったまま通信量を 20 分の 1 にした
- 自分のテーマとの違い：
  - 「エッジで自信があれば終わり、なければ上に送る」という今回の形の原型
  - ただし送る基準は確信度だけで、クラスの重さや回線の劣化は考えていない

### B. 送るかどうかの判定を賢くする

### 論文4
- タイトル：AppealNet: An Efficient and Highly-Accurate Edge/Cloud Collaborative Architecture for DNN Inference
- 著者・年：Min Li, Yu Li, Ye Tian, Li Jiang, Qiang Xu（DAC, 2021）
- URL / DOI：https://doi.org/10.1109/dac18074.2021.9586176
- 査読：あり（国際会議 DAC）
- 何をしたか：
  - エッジのモデルに「この入力は自分で正しく答えられそうか」を予測する部分を足した
  - 答えられなさそうな入力だけをクラウドに送る
- 結果（数字があれば数字で）：
  - 既存の方法と比べて、精度を落とさずに消費電力を最大 40% 以上減らした
- 自分のテーマとの違い：
  - 判定を賢くするのは同じ方向。ただし「正しく答えられるか」だけで、間違えたときの重さはクラスで同じ

### 論文5
- タイトル：EdgeBoost: Confidence Boosting for Resource Constrained Inference via Selective Offloading
- 著者・年：Naina Said, Olaf Landsiedel（DCOSS-IoT, 2024）
- URL / DOI：https://doi.org/10.1109/DCOSS-IoT61029.2024.00013
- 査読：あり（国際会議 DCOSS-IoT）
- 何をしたか：
  - エッジのモデルの確信度を補正（キャリブレーション）してから、送るかどうかを決める
  - 確信度が低いものだけクラウドに送る
- 結果（数字があれば数字で）：
  - 全部クラウドに送る場合と同じくらいの正解率で、通信量を CIFAR-100 で 55%、ImageNet で 29%、Stanford Cars で 20% 減らした
- 自分のテーマとの違い：
  - 確信度は当てにならないことがあるので補正が大事、という教訓は使える
  - ただしふつうの画像データセットで、災害画像や回線の劣化は扱っていない

### 論文6
- タイトル：Optimal Confidence Thresholds for Cooperative Inference in Intelligent Surveillance Systems
- 著者・年：Hyun-Ho Choi, Ki-Ho Lee, Kisong Lee（IEEE Internet of Things Journal, 2025）
- URL / DOI：https://doi.org/10.1109/JIOT.2025.3594344
- 査読：あり（論文誌 IEEE Internet of Things Journal）
- 何をしたか：
  - 監視カメラ向け。しきい値を 2 つ使い、「はっきり陽性」「はっきり陰性」「迷う」に分ける
  - 迷う画像だけをサーバーに送り、必要な精度を守りながら遅延が最小になるしきい値を計算で求めた
  - 何もないのに検知する誤報も考えている
- 結果（数字があれば数字で）：
  - エッジだけより精度が高く、サーバーだけより遅延がずっと小さい（要旨に数字はない。シミュレーションでの評価）
- 自分のテーマとの違い：
  - しきい値を 2 つ使う点、陽性と陰性の間違いを分けて考える点は近い。比べる方式の 1 つにする
  - ただし回線が変わる状況や、災害は扱っていない

### C. 回線に合わせて送り方を変える

### 論文7
- タイトル：Edge-Cloud Collaborated Object Detection via Bandwidth Adaptive Difficult-Case Discriminator（DCSB）
- 著者・年：Zhiqiang Cao ほか（IEEE Transactions on Mobile Computing, 2024）
- URL / DOI：https://doi.org/10.1109/TMC.2024.3474743
- 査読：あり（論文誌 IEEE TMC）
- 何をしたか：
  - 物体検出で「難しい画像」を見分ける判定器をエッジに置き、難しいものだけクラウドの大きなモデルへ送る
  - 回線の状態ごとに判定器を何種類も用意しておき、使い分ける
- 結果（数字があれば数字で）：
  - 物体の 97.26〜97.96% を検出しつつ、クラウドだけの方式より帯域を 74.37〜82.23% 節約した
  - 8 Mbps のとき、分割推論の方式より推論時間を 92.60〜95.10% 減らした
- 自分のテーマとの違い：
  - 回線に合わせて送る基準を変える点は近い
  - ただし「難しいかどうか」で決めていて、クラスごとの見逃しの重さは考えていない

### 論文8
- タイトル：Link-adaptive edge-cloud inference for UAV-based plastic mulch residue assessment
- 著者・年：Xinmiao Zhao ほか（Scientific Reports, 2026）
- URL / DOI：https://doi.org/10.1038/s41598-026-65658-3
- 査読：あり（論文誌 Scientific Reports）
- 何をしたか：
  - ドローンの農業画像（畑に残ったビニール）を、エッジとクラウドで分担して処理する
  - 「回線の速さ」「エッジの確信度」「前の画像からの変化」を 1 つの点数にまとめる
  - 画像ごとに「エッジで終わり／一部だけ送る／全部送る」を決める
  - 4G・5G・Wi-Fi 6 の回線を模擬して評価した
- 結果（数字があれば数字で）：
  - クラウドだけで処理した場合の 97.1% の精度（IoU 0.826）、遅延の中央値 72 ms
  - 回線が急に変わったとき、しきい値が固定の方式より 3.4 倍速く対応した
- 自分のテーマとの違い：
  - ドローン＋回線に合わせて送り方を変える、という点で一番近い
  - ただし、どのクラスを見逃すと困るかという「優先度」は考えていない
  - 対象は農業の領域分割（セグメンテーション）で、災害の画像分類ではない

### D. 端末の台数が増える

### 論文9
- タイトル：MultiTASC++: A Continuously Adaptive Scheduler for Edge-Based Multi-Device Cascade Inference
- 著者・年：Sokratis Nikolaidis, Stylianos I. Venieris, Iakovos S. Venieris（ITU Journal on Future and Evolving Technologies, 2024）
- URL / DOI：https://doi.org/10.52953/tbyb6219
- 査読：あり（論文誌 ITU J-FET）
- 何をしたか：
  - スマートホームのように、たくさんの端末が 1 台のサーバーを共有する場面を想定
  - サーバーが混んできたら、各端末の「送る基準」を自動で変えて、全体の処理量と精度を保つ
- 結果（数字があれば数字で）：
  - 端末 100 台まで、目標の満足率を守りながら一番高い精度を出した
- 自分のテーマとの違い：
  - 「送る基準を状況に合わせて動かす」点は同じ。ただし変える理由はサーバーの混み具合で、回線の劣化ではない
  - 複数のドローンで 1 台のサーバーを使う場合に、将来参考になる

### E. ドローンごとにデータの性質が違う

  - そこで、場面ごとに確信度のしきい値と画像の圧縮（量子化）をまとめて最適化する
- 結果（数字があれば数字で）：
  - データの性質が同じと仮定する方法より精度が上がった（要旨に数字はない）

  - ただし実験は CIFAR-10（ふつうの写真）のシミュレーションだけで、災害画像ではない。クラスの優先度もない

### F. クラスごとに優先度を付ける

### 論文11
- タイトル：ClassyNet: Class-Aware Early-Exit Neural Networks for Edge Devices
- 著者・年：Mohammed Ayyat, Tamer Nadeem, Bartosz Krawczyk（IEEE Internet of Things Journal, 2023）
- URL / DOI：https://doi.org/10.1109/jiot.2023.3344120
- 査読：あり（論文誌 IEEE Internet of Things Journal）
- 何をしたか：
  - 途中で答えを出せる「早期終了」モデルで、出口ごとに答えを出すクラスを選べるようにした
  - 大事なクラスほど浅い層（早い段階）で答えを出し、浅い層はエッジで動かす
- 結果（数字があれば数字で）：
  - 精度を落とさずに、大事なクラスの推論を速くし、計算と時間を減らした（要旨に数字はない。本文は未確認）
- 自分のテーマとの違い：
  - 「クラスごとに重さを変える」という考え方は同じ
  - ただし「1 台の中で計算をどこで打ち切るか」に優先度を使っている
  - 「細い回線で、どの画像を先にサーバーへ送るか」には使っていない

### 論文12
- タイトル：Edge-Prioritize IDS: Zero-Retraining Class Prioritization for Real-Time Edge Intrusion Detection
- 著者・年：Pruthviraj Pawar ほか（Information, MDPI, 2026）
- URL / DOI：https://doi.org/10.3390/info17050451
- 査読：あり（論文誌 Information）
- 何をしたか：
  - 不正アクセス検知で、危険な攻撃のクラスを優先して、早期終了モデルの早い出口で判定する
  - クラスごとの優先度を小さなベクトルで持ち、学習し直さずに優先度を変えられる
- 結果（数字があれば数字で）：
  - 精度は最大 99.6% のまま、優先するクラスの遅延を最大 55%、電力を最大 50% 減らした（NVIDIA Jetson TX2 で評価）
- 自分のテーマとの違い：
  - 優先度を後から変えられる点は、災害の種類ごとに重さを変えたい今回にも使える
  - ただしこれも 1 台の中の計算の打ち切りで、回線で送る順番ではない。対象も不正アクセス検知

### まとめ：どこまで研究が進んでいるか
- 「軽いモデルでふるいにかけ、迷ったものだけ重いモデルに送る」しくみは 2017 年ごろに確立した（A：論文1〜3）
- 今は「いつ・何を送るか」の決め方が研究の中心（B〜E）
  - 判定を賢くする（論文4〜6）、回線に合わせる（論文7、8）、台数（論文9）、データの性質（論文10）
- クラスごとの優先度（F：論文11、12）は、1 台の中の計算の打ち切りにしか使われていない
- 災害ドローン（G：論文13〜17）は、ドローン 1 台の中か、シミュレーションが中心
- この 3 つ（回線に合わせる・クラスの優先度・災害ドローン）を組み合わせた研究は見つからなかった
  - 一番近いのは論文8（ドローン・回線に合わせる）と論文11（優先度の考え方）
  - 調べ方：Google Scholar・arXiv・OpenAlex で約 20 回検索（2026-10-08 時点）
  - 「見つからなかった」は「存在しない」とは違う。IEEE の論文は要旨までしか読めていない

## 2. 技術的な課題のあら捜し
先行研究の弱いところ・まだやられていないことを探す。

| 課題 | どの論文の話か | なぜ問題か |
| --- | --- | --- |
| どのクラスの間違いも同じ重さで扱う | 論文1、3〜10 | 災害では、被災の見逃しは平常の画像を余計に送るよりずっと重い。確信度だけで送ると、自信を持って間違えた被災画像が送られない |
| 回線を通して送る話になっていない | 論文1、11〜16 | 災害時は回線が細く、だんだん悪くなる。1 台の中で速くしても、サーバーまで届くかは分からない |
| クラスの優先度を「計算の打ち切り」にしか使っていない | 論文11、12 | 回線が細いときに「どの画像を先に送るか」には使われていない |
| 回線に合わせるが、優先度がない | 論文7、8 | 回線が細くなると、大事な画像も一律に送られにくくなる |
| 災害の対象・データで評価していない | 論文1〜12 | 監視カメラ・農業・一般の画像が対象。災害画像は平常が大半で偏っており、正解率だけでは良し悪しが分からない |
| 実際の画像で評価していない | 論文6、10、17 | シミュレーションや CIFAR-10 だけで、実際の災害画像でうまくいくか分からない |
| ドローン 1 台の中で完結している | 論文13〜16 | ドローンの軽いモデルが見逃した画像は、だれも確かめられない |

## 3. 新規性
先行研究に「ない」こと。

- 送るかどうかを決めるときに「見逃しの重さがクラスで違う」ことを入れる
  - 被災っぽい画像は、確信度が低くなくても優先して送る
  - 平常で自信のある画像は送らない
- 回線が時間とともに細くなる条件（10Mbps → 1Mbps → 200kbps）で評価する
- 実際の災害空撮データセット（AIDER）で確かめる
- 一文で：エッジ・クラウド協調推論で、災害時の見逃しの重さと回線の劣化を考えた送り方を提案し、AIDER で評価する
- 弱いところ：新規性は「組み合わせ」型。ふつうのカスケードと差が出ない可能性もある（その理由を考えることも結果になる）

## 4. 有効性
それをやると、何が・どれだけ良くなるか。何の数字で示すか。

- 何が良くなるか：
  - 同じ通信量で、被災状況をより早く・漏れなく伝えられる
  - 平常の画像はエッジで落とすので、送るデータ量は大きく減る（AIDER は平常の画像が大半）
- 評価の指標：
  - 災害画像がすべてサーバーに届くまでの時間（一番大事）
  - 災害画像の見逃し率（1 − 災害クラスの再現率）、クラスごとの F1
  - 送ったデータ量（ほぼ変わらないことを確かめる）
- 比べる方式（同じデータ・同じ回線で再現する）：
  - 全部サーバーに送る
  - 全部エッジで処理する（論文13 の EmergencyNet 単独）
  - 確信度が低い画像だけ送る（論文1、3、5 の基本形）
  - しきい値を 2 つ使う（論文6）
