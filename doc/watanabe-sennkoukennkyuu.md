# 先行研究まとめ（watanabe）

## テーマ案
- テーマ：エッジとサーバーで分担する災害画像の分類（エッジ・クラウド協調推論）
  - ドローンの軽い AI で画像をふるいにかけ、迷った画像や被災っぽい画像だけをサーバーの重い AI に送る

### 論文1
- タイトル：NoScope: Optimizing Neural Network Queries over Video at Scale
- 著者・年：Daniel Kang, John Emmons, Firas Abuzaid, Peter Bailis, Matei Zaharia（Proceedings of the VLDB Endowment, vol. 10, no. 11, 2017）
- URL / DOI：https://doi.org/10.14778/3137628.3137664
- 査読：あり（論文誌 PVLDB）
- 役割：基本の形（軽いモデルでふるい、迷ったら重いモデルへ）。比べる方式「確信度が低いものだけ送る」のもと
- 何をしたか：
  - 監視カメラの映像を、まず小さく軽いモデルで見て「何も映っていない」フレームを捨てる
  - 迷ったフレームだけを重いモデルに回す（カスケード）
  - 動画と探す物体に合わせて、軽いモデルとしきい値を自動で選ぶ
- 結果（数字があれば数字で）：
  - 重いモデルだけを使う場合と比べて、精度の低下 1〜5% で、265〜15,500 倍の速さ（実時間比）
- 自分のテーマとの違い：
  - 「軽いモデルでふるいにかけ、迷ったものだけ重いモデルへ」という発想は同じ（この分野の基本形）
  - ただし 1 台の計算機の中の話で、回線を通して送る話ではない
  - どのクラスを見逃しても同じ重さで扱っている

### 論文2
- タイトル：Distributed Deep Neural Networks Over the Cloud, the Edge and End Devices（DDNN）
- 著者・年：Surat Teerapittayanon, Bradley McDanel, H. T. Kung（ICDCS, 2017）
- URL / DOI：https://doi.org/10.1109/icdcs.2017.226
- 査読：あり（国際会議 ICDCS）
- 役割：エッジ・クラウドで分担する形の原型。同じく比べる方式のもと
- 何をしたか：
  - 端末・エッジ・クラウドの 3 段にモデルを分けて置き、まとめて学習する
  - 端末で自信があればそこで答えを出し、なければ上の段に送る
- 結果（数字があれば数字で）：
  - 生のデータをすべてクラウドに送る方式と比べて、精度を保ったまま通信量を 20 分の 1 にした
- 自分のテーマとの違い：
  - 「エッジで自信があれば終わり、なければ上に送る」という今回の形の原型
  - ただし送る基準は確信度だけで、クラスの重さや回線の劣化は考えていない

### 論文3
- タイトル：Optimal Confidence Thresholds for Cooperative Inference in Intelligent Surveillance Systems
- 著者・年：Hyun-Ho Choi, Ki-Ho Lee, Kisong Lee（IEEE Internet of Things Journal, 2025）
- URL / DOI：https://doi.org/10.1109/JIOT.2025.3594344
- 査読：あり（論文誌 IEEE Internet of Things Journal）
- 役割：比べる方式「しきい値を 2 つ使う」のもと
- 何をしたか：
  - 監視カメラ向け。しきい値を 2 つ使い、「はっきり陽性」「はっきり陰性」「迷う」に分ける
  - 迷う画像だけをサーバーに送り、必要な精度を守りながら遅延が最小になるしきい値を計算で求めた
  - 何もないのに検知する誤報も考えている
- 結果（数字があれば数字で）：
  - エッジだけより精度が高く、サーバーだけより遅延がずっと小さい（要旨に数字はない。シミュレーションでの評価）
- 自分のテーマとの違い：
  - しきい値を 2 つ使う点、陽性と陰性の間違いを分けて考える点は近い。比べる方式の 1 つにする
  - ただし回線が変わる状況や、災害は扱っていない

### 論文4
- タイトル：Link-adaptive edge-cloud inference for UAV-based plastic mulch residue assessment
- 著者・年：Xinmiao Zhao ほか（Scientific Reports, 2026）
- URL / DOI：https://doi.org/10.1038/s41598-026-65658-3
- 査読：あり（論文誌 Scientific Reports）
- 役割：一番近い研究①。ドローンで回線に合わせるが、クラスの優先度がない。回線条件の数字の根拠
- 何をしたか：
  - ドローンの農業画像（畑に残ったビニール）を、エッジとクラウドで分担して処理する
  - 「回線の速さ」「エッジの確信度」「前の画像からの変化」を 1 つの点数にまとめる
  - 画像ごとに「エッジで終わり／一部だけ送る／全部送る」を決める
  - 4G・5G・Wi-Fi 6 の回線を模擬して評価した
- 結果（数字があれば数字で）：
  - クラウドだけで処理した場合の 97.1% の精度（IoU 0.826）、遅延の中央値 72 ms
  - 回線が急に変わったとき、しきい値が固定の方式より 3.4 倍速く対応した
- 自分のテーマとの違い：
  - ドローン＋回線に合わせて送り方を変える、という点で一番近い
  - ただし、どのクラスを見逃すと困るかという「優先度」は考えていない
  - 対象は農業の領域分割（セグメンテーション）で、災害の画像分類ではない

  - 精度を落とさずに、大事なクラスの推論を速くし、計算と時間を減らした（要旨に数字はない。本文は未確認）

  - 「細い回線で、どの画像を先にサーバーへ送るか」には使っていない

### 論文8
- タイトル：Edge-Cloud Collaborated Object Detection via Bandwidth Adaptive Difficult-Case Discriminator（DCSB）
- 著者・年：Zhiqiang Cao ほか（IEEE Transactions on Mobile Computing, 2024）
- URL / DOI：https://doi.org/10.1109/TMC.2024.3474743
- 査読：あり（論文誌 IEEE TMC）
- 役割：「送らない方が分割推論より速い」という数字（推論時間 92〜95% 減）
- 何をしたか：
  - 物体検出で「難しい画像」を見分ける判定器をエッジに置き、難しいものだけクラウドの大きなモデルへ送る

- 自分のテーマとの違い：
  - 回線に合わせて送る基準を変える点は近い
  - ただし「難しいかどうか」で決めていて、クラスごとの見逃しの重さは考えていない

## 3. 新規性
先行研究に「ない」こと。

- 送るかどうかを決めるときに「見逃しの重さがクラスで違う」ことを入れる
  - 被災っぽい画像は、確信度が低くなくても優先して送る
  - 平常で自信のある画像は送らない
- 回線が時間とともに細くなる条件（10Mbps → 1Mbps → 200kbps）で評価する
- 実際の災害空撮データセット（AIDER）で確かめる
- 一文で：エッジ・クラウド協調推論で、災害時の見逃しの重さと回線の劣化を考えた送り方を提案し、AIDER で評価する
- 弱いところ：新規性は「組み合わせ」型。ふつうのカスケードと差が出ない可能性もある（その理由を考えることも結果になる）

## 4. 有効性
それをやると、何が・どれだけ良くなるか。何の数字で示すか。

- 何が良くなるか：
  - 同じ通信量で、被災状況をより早く・漏れなく伝えられる
  - 平常の画像はエッジで落とすので、送るデータ量は大きく減る（AIDER は平常の画像が大半）
- 評価の指標：
  - 災害画像がすべてサーバーに届くまでの時間（一番大事）
  - 災害画像の見逃し率（1 − 災害クラスの再現率）、クラスごとの F1
  - 送ったデータ量（ほぼ変わらないことを確かめる）
- 比べる方式（同じデータ・同じ回線で再現する）：
  - 全部サーバーに送る
  - 全部エッジで処理する（論文6 の EmergencyNet 単独）
  - 確信度が低い画像だけ送る（論文1、2 の基本形）
  - しきい値を 2 つ使う（論文3）
  - 提案
